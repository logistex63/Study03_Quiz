# 문항 추가

`$ARGUMENTS`로 받은 카테고리에 새 문항 1개를 만든다. 문항 전체를 보여 주고 사용자가 승인하면 `questions.js`에 넣는다.

## 지켜야 할 것

- **승인 전에는 파일을 고치지 않는다.** 문항을 보여 준 뒤 그 턴을 끝내고 사용자의 답을 기다린다.
- 승인받은 뒤에도 고치는 파일은 `questions.js` 하나뿐이다. 이미 있는 문항은 건드리지 않는다.
- 규칙의 기준은 매번 `CLAUDE.md`를 새로 읽어서 정한다. 아래 설명과 `CLAUDE.md`가 다르면 `CLAUDE.md`를 따른다.
- 확인하지 못한 사실을 확인했다고 쓰지 않는다. 출처 두 곳에서 확인되지 않은 문항은 버리고 새로 만든다.

## 인수

- 첫째 인수는 카테고리다. `한국사`, `세계지리`, `과학`, `예술과 문화` 가운데 하나여야 한다(`예술과 문화`는 띄어쓰기를 포함해 한 인수로 본다).
- 마지막 인수는 난이도다. `쉬움`, `보통`, `어려움` 가운데 하나여야 한다.
- 인수가 빠졌거나 목록에 없으면 문항을 만들지 말고, 쓸 수 있는 값과 예(`/quiz-add 한국사 어려움`)를 알려 주고 멈춘다.

난이도는 문항의 `difficulty` 칸에 인수 그대로(`쉬움`, `보통`, `어려움`) 적는다.

| 난이도 | 기준 |
|---|---|
| 쉬움 | 초·중학교 교과서에 나오고, 대부분 들어 본 사실 |
| 보통 | 고등학교 교과서나 교양 수준에서 한 번 더 생각해야 하는 사실 |
| 어려움 | 교과서 밖의 구체적 사실. 다만 규칙 3에 따라 자료마다 값이 다른 연도·수치는 쓰지 않는다 |

## 순서

### 1. 읽기

- `CLAUDE.md`의 "문항 규칙"과 `PRD.md` 5절(문항 자료 형식과 규칙)을 읽는다.
- `questions.js`를 읽고, 그 카테고리의 기존 문항(문제와 정답)과 마지막 id 번호를 확인한다.

### 2. 문항 만들기

- 기존 문항과 같은 사실을 묻거나 정답이 같은 문항은 만들지 않는다.
- 형식은 기존 문항과 같다: `id`, `category`, `difficulty`, `question`, `choices`(4개), `answer`, `explanation`(한 줄), `source`(`title`, `url`).
- `id`는 카테고리 접두어(한국사 `kh`, 세계지리 `wg`, 과학 `sc`, 예술과 문화 `ac`)에 기존 마지막 번호 다음 번호를 두 자리로 붙인다(예: `kh-11`).
- `answer`는 `choices` 가운데 하나와 글자가 똑같아야 하고, 기존 문항처럼 `choices`의 첫째 자리에 둔다(보기 순서는 앱이 섞는다).
- 오답 보기 3개는 분명히 틀려야 한다. 다른 이름이나 같은 뜻의 표현으로 정답이 될 수 있는 보기, "모두 정답" 같은 보기는 쓰지 않는다.

### 3. 규칙 확인

`CLAUDE.md`의 규칙마다 확인한다.

1. **출처 2곳 이상**: 출처 페이지를 WebFetch로 열어 정답과 해설 내용이 적혀 있는지 확인한다. 다른 기관이나 사이트의 출처를 WebSearch로 하나 더 찾아 열어 같은 내용인지 확인한다. 같은 사이트의 다른 페이지는 두 번째 출처로 치지 않는다. 백과사전, 공공기관, 학술 기관 자료를 우선한다. `source`에는 열어서 확인한 첫째 출처를 적는다.
2. **기준과 시점**: 「가장」, 「최초」, 「처음」, 순위, 수치, 현재 상태(수도, 인구, 기록 등)를 묻거나 시기에 따라 답이 여럿일 수 있으면, 기준과 시점을 문제 문장에 적는다.
3. **값이 다른 사실 금지**: 문제, 보기, 해설에 나오는 연도와 수치가 두 출처에서 같은지 본다. 다르거나 널리 알려진 다른 값이 있으면 그 값을 빼거나 다른 문항으로 바꾼다.
4. **정답과 해설 일치**: `answer`가 `choices`에 정확히 한 번 있는지, 해설이 정답을 설명하는지 다시 읽는다.

하나라도 지키지 못하면 문항을 고치거나 버리고 2단계부터 다시 한다.

### 4. 보여 주고 승인 기다리기

아래 형식으로 보여 준 뒤 **턴을 끝내고 기다린다.**

```
카테고리: (카테고리) / 난이도: (난이도) / id: (id)

문제: (question)
보기: 1) … 2) … 3) … 4) …
정답: (answer)
해설: (explanation)
출처: (source.title) — (source.url)
두 번째 출처: (기관/사이트 이름) — (URL)
```

그 아래에 `questions.js`에 넣을 코드 블록(객체 그대로)을 보여 준다. 규칙 2·3을 어떻게 지켰는지 한두 줄로 덧붙이고, "넣을까요? 고칠 곳이 있으면 알려 주세요."라고 묻는다.
### 5. 답에 따라 하기

- **승인**(예: "넣어", "좋아", "승인"): 6단계로 간다.
- **수정 요청**: 고친 뒤 3단계 규칙 확인을 다시 하고 4단계 형식으로 다시 보여 준다.
- **거절**: 파일을 고치지 않고 끝낸다.
- 애매한 답이면 넣지 말고 다시 묻는다.

### 6. 넣기

- `questions.js`에서 그 카테고리의 마지막 문항 바로 뒤, 다음 카테고리 주석(`// ===== … =====`) 앞에 새 객체를 넣는다. 들여쓰기와 따옴표, 끝의 쉼표는 기존 문항과 맞춘다.
- 넣은 뒤 파일을 다시 읽어 새 문항이 제자리에 있고 `id`가 겹치지 않는지 확인한다.

### 7. 보고

- 넣은 문항의 `id`를 한 줄로 알린다.
- `questions.js`를 다시 세어 카테고리별 문항 수를 표로 보고한다.

| 카테고리 | 문항 수 |
|---|---|
| 한국사 | (개수) |
| 세계지리 | (개수) |
| 과학 | (개수) |
| 예술과 문화 | (개수) |
| 합계 | (개수) |

- 10개보다 적은 카테고리가 있으면 표 아래에 "앱의 자료 검사(카테고리마다 10문항 이상)에 걸립니다"라고 적는다.
